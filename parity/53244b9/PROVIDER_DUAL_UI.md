# 第三方音乐源双 UI 迁移

## 本批接入

| 数据入口 | 手机 UI | 电脑 UI |
| --- | --- | --- |
| QQ／酷狗／YouTube 首页 | 保留推荐歌单、新歌和原生排行榜 | 独立宽屏首页、横向分页封面架和桌面歌曲行 |
| Spotify／YouTube 音乐库 | 歌单／收藏专辑／关注歌手，复用液态分段选择器 | 侧栏独立栏目，专辑方形封面、歌手圆形封面 |
| 本地音乐库 | 歌曲／歌单、分页及新建歌单 | 侧栏歌曲／歌单、桌面歌曲菜单及新建歌单 |
| 第三方排行榜 | 真实 RankingCapability 完整分页 | 发现页不再因缺少 previewTracks 隐藏榜单，也不将预览当完整队列 |
| QQ／酷狗／Bilibili／Jellyfin 登录门控 | 原有账号流程 | 保留桌面布局，按当前来源打开对应账号表单；错误状态也保留登录入口 |

## 数据与生命周期

- 直接调用已存在的 provider 能力。专辑与歌手的曲目详情沿用搜索的双 UI 详情，歌单沿用双 UI 歌单详情。
- 列表每页 50 项，按来源原生 ID 去重；显式“加载更多”，不预先读取整个收藏库。
- 本地音乐读取实际文件索引和本地持久化歌单。UI 桥接 ID 不用于服务读写，`providerTrack`／`providerPlaylist` 保留原始身份。
- 未登录显示登录入口；网络错误显示重试；成功空结果显示空状态。
- Spotify／YouTube 会话变化使音乐库旧组合及协程作用域退出；切换栏目取消该栏目“加载更多”与写入任务。
- Spotify 常规 access-token 刷新不递增会话 revision，避免读取音乐库时重复重启刷新链路。
- Spotify 来源可以在未配置 Client ID 时选择，随后进入已有 Client ID／OAuth 登录表单；没有注入任何 Token 或账号。401 刷新同样接受用户在登录页保存的真实 Client ID。
- 第三方音乐库使用 `MeloXLoginRequestBus` 明确传递来源，避免电脑模式下默认进入网易云手机号表单。
- 手机端保留固定的“音乐库”标题和液态分段选择器，长列表滚动不会带走栏目入口；电脑端使用侧栏和独立歌曲／封面布局。
- 首页／发现按实际 feed 能力过滤；Spotify／Jellyfin／Local 不再进入“未提供首页数据”的页面，Bilibili 保持自己的根页面范围。云盘／播客只属于网易云来源。相关设置值和自定义排序仍保存，不因切换来源重写。
- 电脑侧栏与手机根导航共用来源可用性策略，切换来源恢复该来源自己保存的音乐库栏目。

## 验证范围

本地最终汇总：桌面编译通过；61 suites／297 tests 零失败；12 captures／107 scenes／139 assertions 零失败。详见 `evidence/provider-dual-ui/summary.json`。旧 v3 首页回放仅作导航取证，不计最终内容验收；以 v5 酷狗／v6 QQ 的实际歌曲行断言补验为准。

`tools/capture_provider_collections.py` 使用隔离 home 和真实指针／滚轮／键盘事件：

- Local：扫描 55 个生成的真实 WAV，读取第二页、新建本地歌单并打开／返回真实详情。
- Spotify／YouTube：未登录条件下切换歌单／专辑／歌手，再进入实际账号页。
- 每个来源分别运行手机与电脑 UI；截图、semantics、capture.json 和 Gradle 日志输出到指定目录。
- QQ／酷狗／Bilibili／Jellyfin 另回放电脑登录门控，断言打开正确的来源表单。
- `tools/capture_provider_home.py` 严格访问真实公开 QQ／酷狗接口，回放首页榜单和发现页榜单进入／返回；服务不可用时失败并保留原日志。

未登录回放不能证明私人账号的实际收藏内容；生成的本地 WAV 不是在线服务替身。
Windows 发行的验收应继续以完整下载的发行 ZIP 和对应来源 SHA 为准。

## 失败回放的处理

- v1 长列表 `reveal` 在 LazyColumn 离屏节点附近来回滚动；v2 单次大滚轮事件的截图又早于惯性结束。正式回放使用真实滚轮事件后等待停稳，并从原始 semantics 独立检查加载数从 50 增至 55。
- v2 Spotify 的来源被空构建 Client ID 隐藏，实际误入网易云；YouTube 电脑登录按钮也误开网易云表单。v3 修复来源可选与登录来源传递后，YouTube 双 UI 以及 QQ／酷狗／Bilibili／Jellyfin 电脑账号表单通过。
- v3 Spotify 在未登录时把账号读取的“请先登录”异常只呈现为重试；最终改为按 UserLibraryCapability 的可空账号契约返回未登录状态。
- v3 Local 手机详情已显示真实新建的歌单，但回放断言误用了不存在的 `playlist-header`；最终断言使用实际 `playlist-tracks` 与歌单标题，保留失败截图，不把原失败计为通过。
- v3 QQ／酷狗的页面进退断言虽通过，整理原图时发现酷狗详情及 QQ 的 MV 榜为 0 首；这两组旧回放只保留为导航取证，不计歌曲内容验收。酷狗 KMR v2 把 hash／毫秒时长放在 `audio_info`，旧解析丢失父子关联；补齐解析并回归专辑、封面、时长及 album_audio_id。QQ MV 榜属于视频目录，未实现视频能力时不作为歌曲榜单展示。
- 公开回放加强为首页和发现页均必须存在 `desktop-collection-track:` 真正歌曲行，选择真实公开的 QQ 62 榜与酷狗 49223 榜重新验收，不以“详情页面存在”替代“歌曲已加载”。
