# 网易云搜索请求治理

## 已确认的请求来源

- 桌面建议词300ms、正式搜索320ms同时触发，短暂输入停顿就会发出两路请求。
- 歌曲搜索已经绑定协程取消，但专辑/歌手/歌单/播客/用户搜索与建议词没有传入owner，输入替换后旧HTTP调用仍会继续。
- 重复关键词、重复提交和分类往返没有搜索响应缓存；HTTP层缓存无法有效复用带随机头部和加密参数的POST。
- 网易云API各模块共用连接池，但没有共用发起频率、并发预算或限流冷却。

## 修复

1. 桌面正式搜索改为停顿800ms；显式提交仍立即执行。手机版保留1500ms。音乐库范围也先等待输入稳定，减少输入期间反复加载收藏库。
2. 建议词等待600ms，少于两个字符不请求；所有搜索分类与建议词均绑定实际OkHttp调用的协程取消。
3. 两个搜索客户端共享120秒内存响应缓存，最多64条。按HTTP客户端、Cookie指纹、接口、完整查询参数隔离；相同请求并发合并，返回JSON副本，失败/取消不缓存。缓存不写磁盘，不缓存写操作。
4. 网易云API跨域统一最多2个处理中请求，相邻请求发起至少350ms。仅覆盖网易云API路径，封面、音频CDN和其他服务不进入队列。
5. HTTP429、业务429/-462及明确的频繁请求消息触发至少60秒冷却；支持Retry-After秒数及HTTP日期。冷却期间排队/新API请求本地失败并提示剩余秒数，不自动重试，不堆积待恢复请求。
6. 顺带减少首页后台竞争：有服务器栏目内容时不再请求对应fallback；“全部”区域热歌复用同一份请求结果。

## 验证

- shared：58 suites / **285 tests**，0 failures/errors/skipped。
- 协议测试：真实加密EAPI经过本地HTTP服务器；相同关键词跨客户端连续搜索3次仅1次HTTP；更换分类产生独立请求；歌曲、媒体分类、建议词替换时实际Call取消。
- 请求治理测试：并发重复合并、会话/分类隔离、缓存过期、JSON副本、失败与取消不复用；跨API主机共享冷却、音频不受冷却影响、普通登录错误不误判、请求发起间隔与并发上限。
- 生产界面真实公开搜索回放 `capture_desktop_search_scroll.py`：13 scenes；建议词和专辑真实加载，工具栏位置不变，鼠标/离屏Touch拖动位置0→112→224。无物理触屏验收。
- 桌面编译通过。证据在 `evidence/netease-search-traffic/`。

这些验证证明客户端请求减量、取消和冷却机制有效；尚不证明网易云对某个账号/IP已有的风控已经解除，也不构成长期不再限流的保证。
