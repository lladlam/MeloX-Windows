# Android 功能对齐执行计划

以 `FEATURE_SURFACE_AUDIT.md` 和 `ANDROID_PARITY_20261030.md` 为索引；Android 工作区为只读参考。每个任务以真实业务接线、针对性回归、双布局实际输入（涉及界面时）及文档记录为完成条件。平台或账号依赖的验证独立记录，不以模拟替代实机结论。

## 实施顺序

1. **公共业务及页面缺口**：逐项核对首页推荐、播客、来源详情分页、歌曲百科和菜单，优先修复能在现有播放、收藏及来源链中实际使用的问题。
2. **歌词与图片分享**：补齐多行选择、长文本、来源封面、翻译／罗马音和多布局消费者；保留无时间轴语义与真实来源身份。长文本图片与 Jellyfin 受保护封面已接线并有本地回归，原生保存和私人服务器待验证。
3. **语言、引导、法律和关于**：核对当前 Android 资源与 Windows 平台差异，先建立可重复导出与语言回退，再覆盖两套界面和独立重启；逐项适配引导和平台文案。
4. **云控、主题与规则**：按已签名 schema 逐字段核对生产消费者，独立验证回退和生命周期；脚本能力须有真正受限的执行后端及完整权限边界。
5. **Windows 平台后端**：系统媒体控制、USB 独占和 MiPlay 分别设计、实现并接实际播放；针对具体设备能力和失败路径验证。需要真实设备的部分记录为待实机验收。
6. **账号和互联**：YouTube 会话隔离、来源账号及收藏写入、跨机 LAN／DLNA 和物理播放按真实能力补齐；真实账号和硬件验收分别记录。

## 每批交付

- 对照最新源码、现有实现和未完成清单，明确本批行为及依赖。
- 实现实际消费者和失败回退，保留已有双布局、用户资料和播放链。
- 运行有意义的定向测试；涉及 UI 的验收使用实际鼠标、滚轮和键盘，语义树仅用于定位和断言。
- 更新对照文档，正常提交并推送 `main`。Windows CI 完成后完整下载发行 ZIP，独立核对版本戳、全部 CRC、资源及原生库并保存结果。
- 已发布的 `v0.1.0` 保持其原有版本范围；新的 CI 产物不冒充已发布版本。
